# Slipstream v0.2.34 Release Design

**Date:** 2026-08-02

**Status:** approved by the user
**Canonical repository:** `Schero94/slipstream`

## Objective

Ship the already measured cross-engine coding contract as Slipstream v0.2.34.
The release must make Tools and JSON Schema available through the same Chat UI
and OpenAI request shape on Metal/llama.cpp and MLX/oMLX, while retaining the
engine-specific attachment and performance controls.

## Release scope

- Port the validated common Tools/JSON UI and request builder.
- Add the bounded internal MLX `contract` profile used for structured prompts.
- Package and verify the xgrammar runtime dependencies.
- Port the active-bank-safe MLX expert-cache eviction fix.
- Preserve MLX-only image/document handling and Metal-only Compact/Grammar knobs.
- Track the text runtime resources needed to reproduce the public bundle.
- Publish honest release notes and update GitHub Pages with measured evidence.

## Artifacts

- Versioned source and tag `v0.2.34` on `main`.
- A macOS `.dmg` and `.zip` attached to the GitHub Release.
- A locally installed and smoke-checked `/Applications/Slipstream.app` v0.2.34.
- Updated GitHub Pages from `main:/docs`.

The release follows the existing unsigned/unnotarized project policy. It does not
claim Apple notarization unless a configured identity and successful notarization
are independently verified during the build.

## Gates and failure policy

Before any push or tag:

1. Static UI contracts, EN/DE parity, Rust tests, resource consistency, and the
   relevant oMLX grammar/tool tests must pass.
2. The release build must produce a valid `.app` and `.dmg` carrying version
   0.2.34 and the staged llama.cpp/oMLX resources.
3. The built app must be installed and pass a lightweight launch/static smoke.
4. Release assets must have recorded SHA-256 digests.

A failed gate stops the release. No tag, partial GitHub Release, or Pages claim is
published from a red build. If failure occurs after an external mutation, repair
or remove the incomplete external object before reporting completion.

## Publication order

1. Commit the validated source, tests, release notes, and Pages changes.
2. Push `main` and verify the remote commit.
3. Create and push annotated tag `v0.2.34`.
4. Create the GitHub Release and upload both assets.
5. Verify GitHub Pages reports `built` at the release commit and inspect the live
   page plus public download links.

## Honest limits

- Bundled Granite validated the Metal protocol, SSE, cancellation, and JSON
  Schema, but did not emit a tool call. Metal tool-selection quality is not a
  release claim.
- The bounded oMLX structured-request profile is safer and faster than the tested
  fallback, but is not the ordinary-chat throughput peak.
- The qualified Metal Q5 result applies only to cache=10 GiB, headroom=3 GiB,
  io=4, compact slots, and draft disabled.
